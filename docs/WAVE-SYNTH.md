**Ethos: show, don't tell.** Every control draws what it does to the sound.
Labels come second. Panels are tight. Modules have fixed widths. Nothing is truncated.

The engine maps values to units. The page draws from the raw values. Both sides use only the mappings in this table.

**Modulation:** `mods: [{src, dst, amt, curve, via}]`.
- `src`: one of `env1 env2 env3 lfo0 lfo1 lfo2 lfo3 macro0..7 vel note mw at rand`.
- `dst`: any numeric patch key, for example `osc0.pos` or `filt0.cut`.
- `amt`: −1..1, added to the normalised value, then clamped to 0..1.
- `curve`: `lin exp log s`.
- `via`: a source key or null. When set, `amt` is scaled by that source.
- LFOs output −1..1. Envelopes, macros, velocity and the mod wheel output 0..1.

## Tables

- **Storage:** frames of 2048 samples, up to 256 frames. Any frame size from 64 to 4096 is resampled to 2048 in the spectrum on import.
- **Built-in tables:** `Formant Sweep`, `Glass Organ`, `Vowel Ah–Oo`, `Hollow Pulse` and `Grit Saw`. They are generated by the additive recipes in the kit's `TABLES`, rendered at 2048 samples per frame.
- **Engine reads:** band-limited mipmaps, 11 levels, built off the audio thread. The engine reads with cubic Hermite interpolation and crossfades between frames.

## Engine placement

- **A third deck.** `engine::Decks` gets a `synth` deck alongside `main` and `prism`.
- **Always running.** It has no transport and renders whenever a voice sounds.
- **Mixed early.** It is summed before the master soft ceiling, scope, meters and capture, so it is heard, metered and recorded like everything else.
- **Real-time safe.** Notes, controls and live parameter writes reach the audio thread through lock-free queues or atomics. Nothing allocates or locks in the callback. Patches and tables are built off-thread and adopted through `pending_*` slots, the engine's existing pattern.
- **MIDI** comes in through `midir`, opened lazily. Its events go into the same note queue.

## As built (engine and server, 7 Nov 2026)

**Keys added after the contract**, accepted, stored and saved like the rest. They are appended to
the `wave` crate's key table, so every earlier id keeps its number.

| Key | Range | Engine |
|---|---|---|
| `lfoL.smooth` | 0..1 | one-pole lag on the LFO, `v · 200` ms, per voice |
| `lfoL.rise` | 0..1 | fade-in from the note's start, `v · 2` s |
| `voice.mpe` | 0/1 | stored only |
| `fxI.on`, `fxI.kJ` (I = 0..4 Drive Chorus Delay Reverb EQ, J = 0..2) | 0..1 | the master chain, below |

**The master chain** (`wave/src/master_fx.rs`) runs on the synth's output after `master`, in the
page's order. Chorus, Delay, Reverb and EQ are the shared `prism-fx` effects, built once with the
synth and run fully wet; the chain does every mix. `fxI.on` crossfades a unit in or out over 10 ms;
a unit all the way out is skipped (bit-exact) and is cleared when it next comes in.

| Unit | k0 | k1 | k2 |
|---|---|---|---|
| Drive (written here) | `tanh(x·d)/tanh(d)`, `d = 1 + k0·12` | tone: one-pole low-pass at `1000·20^k1` Hz | dry/wet crossfade |
| Chorus (`white-chorus`) | rate `0.1·40^k0` Hz | depth `k1·8` ms around 12 ms | dry/wet crossfade |
| Delay (`echo`) | time `20 + k0·980` ms | feedback `0.15 + k1·0.8` | echoes added to the dry at `k2` |
| Reverb (`dattorro-plate`) | decay `0.2 + k0·0.7`, predelay `k0·30` ms | damping `k1·0.9` | equal-power mix |
| EQ (`eq`) | low shelf 100 Hz | bell 1 kHz, Q 0.7 | high shelf 8 kHz; each `(k − 0.5)·30` dB |

Defaults: Drive off (knobs at the mock-up's 0.45, 0.3, 0.7), Chorus 0.35, 0.5, 0.25, Delay 0.4,
0.35, 0.15, Reverb 0.45, 0.45, 0.2, EQ flat. The mock-up's all-on settings made the default patch
about 6 dB louder; these move it by under 2 dB.

**Telemetry**, beyond the table above: a voice's `stage` is one of `a d s r`; `lfo` is each LFO's
**phase**, 0..1 (what the page draws), with `lfoPhase` the same and `lfoValue` the output −1..1;
`wave` is the last 256 output samples; `device` says whether an audio device is open. With no
device there are no voices.

**Routes, beyond the table above.**
- `POST /api/wave/param` answers `{ok, key, value, live}` with the value as stored (clamped).
  A number reaches the engine as a live knob move; a mode, table name or LFO shape as a whole
  compiled patch. `live:true` is heard and not stored.
- `POST /api/wave/control` also takes `{at}` (aftertouch) and `{allOff:true}`.
- `GET /api/wave/tables` rows carry `builtin`.
- `POST /api/wave/table` takes 1–256 frames of one length, 64–4096 samples. A built-in is never
  replaced: an edit of one is stored as `<name> (edited)` and the reply names it.
- `POST /api/wave/table/import` takes `mode` `count`, `note`, `pitch` or `spectral`, and `grain`;
  **every mode slices by count for now and `grain` is ignored.** `sound` is library-relative.
- `POST /api/wave/presets {name, remove:true}` (or `hidden:true`) unlists; the file stays.
  `{name, tags}` without `patch` saves the current patch.
- Unknown keys, bad values and bad mod rows are `400 {"error": …}`.

**Data:** `<data>/wave/patch.json`, `<data>/wave/tables/<name>.wav` (mono 32-bit float, Serum
`clm ` chunk `<!>N …` giving the frame length), `<data>/wave/presets/<name>.json`.

**Tables are built off the request thread** (a fifth of a second for 64 frames, most of a second
for 256). An oscillator keeps its table until the new one is ready.

**MIDI** (`server/src/midi.rs`): every input port, every channel, opened on the first `/api/wave/*`
request and rescanned every 3 s. Note on/off (velocity 0 is off), CC 1 mod wheel, pitch bend,
channel aftertouch, CC 120/123 all notes off. `MGL_NO_MIDI` keeps it closed (the tests set it).

**Mix:** the synth is summed into the grain deck before its soft ceiling, capture, scope and
spectrum, on the playing and the stopped path. A capture armed while the grain transport is
stopped therefore records in wall-clock time. The Prism deck still sums after the ceiling.

## v8 (RJ, 10 Nov 2026): everything maps, and the FX view is a board

The mock-up is `docs/mockups/wave-synth-v8.html` (Play and Matrix from F, FX from G). This section is the engine
and server half (Phase 2 of the build plan); the page is Phase 3.

### Modulation

- **Every numeric key is a target**, the modulators' own included: LFO rate, sync, smooth and rise, envelope
  times, tempo.
- **Per voice.** ENV 2–4, the amp envelope and the per-note LFOs (Trig, Env) read the voice's modulated values
  every control block (32 samples), so modulating an attack, a decay or a rate takes effect mid-note.
- **Shared.** Free LFOs and board controls are the same for every voice. Once per block they hear the matrix with
  the **shared sources**: this block's macros, mod wheel and aftertouch; each free LFO as the last block left it;
  and the per-note sources (ENV 2–4, velocity, note, rand, per-note LFOs) of the **newest sounding voice**, or 0
  when nothing sounds.
- **Loops are one block late.** LFO 1 → LFO 2 Rate with LFO 2 → LFO 1 Rate is stable and never solved within a
  block.
- **Choice keys** became targets in v8b (below); `voice.mode`, `oscN.route` and `lfoL.mode` are still not.
- The matrix marks what it touched in a `u128`, so there may be at most 128 numeric keys (125 today).

### The board

The patch's `board` replaces the fixed master chain. It is also what a board preset holds.

```json
{"name": "Glass Split",
 "nodes": [{"id": "ch", "kind": "fx:hp-chorus", "x": 144, "y": 16, "on": true, "params": {"rateHz": 0.6, "depth": 38}}],
 "cables": [{"from": ["invoice", "o"], "to": ["ch", "i"]}]}
```

| Kind | Ins | Outs | Controls (real units) |
|---|---|---|---|
| `in:voice` | | `o` | `level` 0..1 |
| `in:osc0` `in:osc1` `in:osc2` `in:sub` `in:noise` | | `o` | `level` 0..1 |
| `out` | `i` | | |
| `fx:<id>` | `i` | `o` | the effect's own, as `GET /api/wave/fx` lists them |
| `wave:drive` | `i` | `o` | `drive` `tone` `mix` 0..1: the old chain's Drive |
| `split` | `i` | `o0` `o1` (`o2`) | `outs` 2..3 |
| `mix` | `i0` `i1` (`i2` `i3`) | `o` | `ins` 2..4, `l0`…`l3` −60..6 dB |
| `gain` | `i` | `o` | `db` −24..24 |
| `pan` | `i` | `o` | `pan` −100..100 |
| `drywet` | `i` `ret` | `send` `o` | `wet` 0..100 % |

- **Inputs.** `in:voice` is everything after the filters. The others are sends: each source before its filter,
  after the amp envelope and velocity, summed over the voices. `master` scales every input, as it scaled the old
  chain's. A level is heard squared (the synth's level law).
- **Effects.** `fx:<id>` is any of the 82 in FX-LIST: the `prism-fx` catalogue without `tremolo`, `decimator`,
  `multi-delay` and `stereo-matrix`, which the exact Hyperprism ports replaced. Each effect does its own wet and
  dry. Convolution and Spectral Dynamics take a sound (v8b, below). No effect's latency is compensated.
- **Laws.** Mix: each in at its level, −60 dB is silence. Gain: `10^(db/20)`. Pan: a constant-power balance, left
  `cos(max(p, 0)·π/2)`, right `cos(max(−p, 0)·π/2)`, `p = pan/100`; the centre is unity. Dry/wet: `send` is `i`;
  `o` is `i·(1 − w) + ret·w`, `w = wet/100`. Gains ramp across each block.
- **Cables.** An out feeds any number of ins; cables into one in are summed. A cable may not repeat another or
  close a loop. Dry/wet is two stages, so `send` → branch → `ret` is allowed and `o` → `ret` is a loop.
- **Switched off.** A node fades over 10 ms to its main input (`i`; `i0` for a mix) and is then skipped,
  bit-exact; an effect is cleared when it comes back in. An input switched off is silent. Split and out ignore
  the switch.
- **Limits.** 64 nodes, 256 cables, one `out` (none is silence). An id is 1 to 64 characters without `:`.
- **What is stored is complete.** Every node lists every control, in its kind's order, clamped. A control left
  out of a posted board takes its default.

### Real time

- **Compiled off the audio thread.** `wave::BoardPlan::compile` orders the stages, builds every kernel and gives
  every out port a block buffer.
- **Swapped in like a table.** `WaveShared::set_board` compiles at the device's rate into a pending slot, and the
  callback swaps it in.
- **Crossfaded.** The new board fades in over 10 ms while the old one fades out. The old plan then goes back
  through a return slot and is dropped on the server's thread.
- **Controls stay live.** A board that differs from the running one only in its controls and switches is not
  rebuilt, which would cut its tails. Each change is a live write through the event queue, tagged with the
  board's signature (`Board::sig`, its node ids and kinds), so a write meant for another board is dropped.
- **Board controls are mod targets.** A mod row's `dst` may be `board:<nodeId>:<key>`, in the same `mods` list
  (the 64 rows are shared). It moves the control in the control's own normalised range (log where the descriptor
  is log), with the shared sources. Rows naming a node or control the board lacks are kept and do nothing.
  `outs` and `ins` are not targets.
- **Tested.** `tests/no_alloc.rs` renders a ten-node board with a send, live writes, mod rows, a switch and a
  swap, and counts no allocation.

### Migration

A patch with no `board` (every patch before v8) is given one as it is read. Its fixed chain becomes Voice → Drive
→ Chorus → Delay → Reverb → EQ → Out, with all six inputs on the left edge:

| Node | Kind | Set from |
|---|---|---|
| `drive` | `wave:drive` | `drive`, `tone`, `mix` = `fx0.k0..k2` |
| `chorus` | `fx:white-chorus` | rate `0.1·40^k0` Hz, depth `k1·8` ms, delay 12 ms, feedback 0, wet `k2`, dry `1 − k2` |
| `delay` | `fx:echo` | time `20 + k0·980` ms, feedback `0.15 + k1·0.8`, damping 0.2, wet `k2`, dry 1 |
| `reverb` | `fx:dattorro-plate` | decay `0.2 + k0·0.7`, predelay `k0·30` ms, damping `k1·0.9`, wet `sin(k2·π/2)`, dry `cos(k2·π/2)` |
| `eq` | `fx:eq` | bands 1, 2 and 6 at `(k − 0.5)·30` dB, band 2's Q 0.7, the high-pass off |

- Each node is switched as its `fxI.on`.
- The board renders the old chain **bit for bit** (`board/tests.rs`, `tests/board.rs`).
- The `fx*` keys stay in the key table so ids keep their numbers. Once a patch has a board, nothing reads them.
- A synth never given a board still runs `master_fx.rs`, which stays as the parity reference.
- **Fixed on the way:** the old chain's switch stepped a fade's worth out and back every other sample while a
  unit was fully in. That was a 0.2 % ripple of its mix at a quarter of the sample rate. The board and the chain
  now both hold still.

## v8b (RJ, 10 Nov 2026): what v8 left out

This is the engine and server half (Phase A of `PLAN-V8B.md`); the page is Phase B.

### A matrix row switched off stays off

- A mod row has `on`: `{src, dst, amt, curve, via, on}`. A row without it is on, so every older patch loads as it
  was.
- An off row is kept, saved and listed (`GET /api/wave/patch`, `POST /api/wave/mods`, board presets' `mods`). It
  moves nothing: not a key, not a choice, not a board control, and telemetry does not report it.
- The 64-row limit counts off rows. `on` that is not `true` or `false` is a 400.

### Choice keys are mod targets

The targets, with their options in order:

| Key | Options | Heard |
|---|---|---|
| `oscN.warpJ.mode` | `off bend sync pwm fold mirror asym quant fm` | per voice, crossfaded |
| `oscN.fx.mode` | `off chorus crush drive delay phaser ring comb` | per voice, crossfaded |
| `oscN.table` | the table bank, below | per voice, crossfaded |
| `filtK.type` | `lp bp hp notch comb form` | per voice, crossfaded |
| `filt.route` | `serial parallel split` | for every voice, reset cleanly |
| `lfoL.shape` | `sine tri up down square steps smooth drawn` | per voice for a Trig or Env LFO, for every voice for a Free one; no reset |

- **The rule.** The base option's index is normalised to 0..1 over its list; the rows' sum (`amt · curve(src) ·
  via`, as for a numeric key) is added and clamped once; the result is stepped to the nearest option, halves up.
  So `+1` on a warp mode at `off` is `fm`, and `amt` `1/(n − 1)` moves a key one option.
- **When.** At the next control block (32 samples). A per-voice key hears the voice's sources; a shared one hears
  the shared sources, as free LFOs and board controls do, so it follows its LFO a block late.
- **Crossfaded** (warp modes, tables, the oscillator effects, filter types): the switching block is played both
  ways and crossfaded across the block. The oscillator renders a second time from a copy of its state, so both
  start from the same phases. The time-domain effects run old and new from the same state, and while a row moves
  `oscN.fx.mode` the effect's line is fed in every mode, so a chorus or delay switched in reads the sound's past
  instead of an empty line. A filter's old type runs over a copy of the block and the new one starts clean.
- **Reset cleanly** (`filt.route`): two routings would have to run the same filters, so the voice's output fades
  out across one block on the old routing, its filters are cleared, and it fades back in across the next.
- **LFO shape**: the LFO takes its new wave at the phase it is at. Its value may step there, as a square wave's
  does, and every destination ramps it across a block as it ramps any modulation.
- **Not clicks.** `tests/choice.rs` toggles each kind a dozen times in two seconds on a low sine and holds the
  worst step to what the two options do held still, plus a block's share of the gap between them.
- `tests/no_alloc.rs` steps every kind with fast LFOs and counts no allocation.

**The table bank.** `oscN.table` steps through the five built-ins in their order (`Formant Sweep`, `Glass Organ`,
`Vowel Ah–Oo`, `Hollow Pulse`, `Grit Saw`), then each table an oscillator plays that is not a built-in, once, in
oscillator order. An oscillator's own table is its base. While the patch has a row onto a table (switched on), the
server builds the five built-ins off the request thread and hands them to the engine (`Synth::set_bank_table`, a
pending slot and a return slot each); once given they stay, about 28 MB. A step to a table not there yet keeps the
oscillator on its own.

**Telemetry.** `GET /api/wave/state`'s `mod` also names each choice key that has rows, with the option it is at:
`{"osc0.warp0.mode": "fold", "osc1.table": "Glass Organ"}`, the newest voice's, or the shared one's for
`filt.route` and a free LFO's shape and when nothing sounds.

### Convolution and Spectral Dynamics on the board

- An `fx:convolution` or `fx:spectral-dynamics` node has `sound`: a library path, or `null`. Convolution takes it
  as its impulse response, Spectral Dynamics as its threshold sound (used when its `useSound` is on). Any other
  node with a sound is refused.
- **Off the audio thread.** The server decodes the file (up to 8 s, as the rack does, into the sounds the rack's
  effects share) before the board goes to the engine; `BoardPlan::compile_with` hands it to the kernel before the
  plan is swapped in. A changed sound is new structure: a new plan, crossfaded in. A sound decoded after its
  board was compiled has the board compiled again.
- **No sound.** A Convolution node with none, or one that could not be read, passes its input through, to the bit.
  Spectral Dynamics with none keeps its level-only mode, as in v8: it runs as with `useSound` off.
- **Routes.**
  - `POST /api/wave/board/param {node, key: "sound", value: path | null, live?}`. The file must be in the library
    and decode; otherwise 400 and nothing changes. The reply is `{ok, node, key, value, soundState, live}`.
  - A whole board (`POST /api/wave/board`, presets) may name any path; one that cannot be read is kept.
  - The replies of `GET`/`POST /api/wave/board` give each sound node `soundState`: `loaded`, `none` or
    `unreadable`. The stored board (and `GET /api/wave/patch`) carries `sound` only.
  - `GET /api/wave/fx` gives those two effects `sound: {key, label}` (`impulse`/`Impulse`,
    `thresholds`/`Threshold sound`), for the page's picker.
